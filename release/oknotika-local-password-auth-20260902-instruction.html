1. Проверка базы, staging и backup

Команды ниже не меняют production до завершения backup. Если путь или project name на реальном VPS отличается, остановиться и согласовать его, а не подставлять догадку.

set -euo pipefail
export OKNOTIKA_ROOT=/var/home/oknotika
export OKNOTIKA_PATCH=/private/incoming/oknotika-local-password-auth-20260902.zip
export OKNOTIKA_STAGE=/var/home/oknotika-local-auth-stage-20260902
export OKNOTIKA_BACKUP="/var/backups/oknotika/local-auth-$(date -u +%Y%m%dT%H%M%SZ)"
export OKNOTIKA_ACTIVE_PROJECT=oknotika
export OKNOTIKA_COMPOSE="$OKNOTIKA_ROOT/deploy/docker/docker-compose.yml"
export OKNOTIKA_COMPOSE_ENV="$OKNOTIKA_ROOT/admin-app/data/private/compose.env"
sudo test -f "$OKNOTIKA_PATCH"
sudo test -f "$OKNOTIKA_COMPOSE"
sudo test -f "$OKNOTIKA_COMPOSE_ENV"
sudo test -f "$OKNOTIKA_ROOT/admin-app/src/auth/oidc.js"
sudo test -f "$OKNOTIKA_ROOT/deploy/docker/secrets/telegram-oidc-client-secret.example"
sudo test ! -e "$OKNOTIKA_STAGE"
sudo test ! -e "$OKNOTIKA_BACKUP"
sudo install -d -o root -g root -m 0700 "$OKNOTIKA_STAGE" "$OKNOTIKA_BACKUP"
sudo unzip -q "$OKNOTIKA_PATCH" -d "$OKNOTIKA_STAGE"
test "$(sudo find "$OKNOTIKA_STAGE" -mindepth 1 -maxdepth 1 -type d -printf '%f\n' | sort | tr '\n' ' ')" = 'admin-app deploy '
test "$(sudo find "$OKNOTIKA_STAGE" -type f | wc -l | tr -d ' ')" = 32
sudo test ! -e "$OKNOTIKA_STAGE/public-app"
sudo curl --fail --silent --show-error https://oknotika.ru/ --output "$OKNOTIKA_BACKUP/public-home.before"
sudo curl --fail --silent --show-error https://oknotika.ru/articles/ --output "$OKNOTIKA_BACKUP/public-articles.before"
sudo tar -C "$OKNOTIKA_ROOT" --exclude=admin-app/data -cpf "$OKNOTIKA_BACKUP/source-before.tar" admin-app deploy
sudo install -o root -g root -m 0600 "$OKNOTIKA_COMPOSE_ENV" "$OKNOTIKA_BACKUP/compose.env.before"

Для согласованного backup DB/WAL и остальных bind-mounted данных на короткое время остановить только текущий admin container. Прежний container запускается напрямую даже если production использовал отдельный relay override.

set -euo pipefail
export OKNOTIKA_ADMIN_CONTAINER="$(sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_COMPOSE_ENV" ps -q admin)"
test -n "$OKNOTIKA_ADMIN_CONTAINER"
restart_old_admin() {
  backup_status=$?
  trap - EXIT
  set +e
  sudo docker start "$OKNOTIKA_ADMIN_CONTAINER" >/dev/null
  exit "$backup_status"
}
trap restart_old_admin EXIT
sudo docker stop "$OKNOTIKA_ADMIN_CONTAINER" >/dev/null
sudo tar -C "$OKNOTIKA_ROOT" -cpf "$OKNOTIKA_BACKUP/admin-data-before.tar" admin-app/data
sudo docker start "$OKNOTIKA_ADMIN_CONTAINER" >/dev/null
trap - EXIT
if sudo test -f /etc/nginx/conf.d/oknotika-docker.conf; then
  sudo install -o root -g root -m 0600 /etc/nginx/conf.d/oknotika-docker.conf "$OKNOTIKA_BACKUP/host-nginx.conf.before"
fi

Скопировать оба tar-файла и старый Compose env в encrypted off-host storage. Не публиковать backup: в admin-data-before.tar находятся private data и прежние runtime credentials.

3. Логин/пароль и безопасный restart

Helper запускается от root, сам скрыто спрашивает логин и пароль дважды, принимает пароль только через stdin, создаёт стойкий versioned scrypt record, SQLite snapshot и отзывает старые sessions. Не создавать username/hash вручную.

set -euo pipefail
sudo env \
  OKNOTIKA_ROOT="$OKNOTIKA_ROOT" \
  OKNOTIKA_ACTIVE_PROJECT="$OKNOTIKA_ACTIVE_PROJECT" \
  OKNOTIKA_COMPOSE_ENV="$OKNOTIKA_CANDIDATE_ENV" \
  "$OKNOTIKA_ROOT/deploy/docker/configure-local-credentials.sh" \
  | sudo tee "$OKNOTIKA_BACKUP/credential-setup-result.json"

Сохранить из JSON имя local-credential-… snapshot: оно нужно для credential-rollback. Сам пароль или hash в JSON не выводятся.

set -euo pipefail
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_CANDIDATE_ENV" up --detach --no-build --force-recreate --wait --wait-timeout 120 admin
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_CANDIDATE_ENV" ps
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_CANDIDATE_ENV" logs --no-color --tail 100 admin
curl --fail --silent --show-error https://admin.oknotika.ru/login | grep -F 'name="password"' >/dev/null
test "$(sudo docker port "$(sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_CANDIDATE_ENV" ps -q admin)" 8000/tcp)" = '127.0.0.1:8000'

sudo nginx -t
sudo systemctl reload nginx
sudo curl --fail --silent --show-error https://oknotika.ru/ --output "$OKNOTIKA_BACKUP/public-home.after"
sudo curl --fail --silent --show-error https://oknotika.ru/articles/ --output "$OKNOTIKA_BACKUP/public-articles.after"
sudo cmp "$OKNOTIKA_BACKUP/public-home.before" "$OKNOTIKA_BACKUP/public-home.after"
sudo cmp "$OKNOTIKA_BACKUP/public-articles.before" "$OKNOTIKA_BACKUP/public-articles.after"

Login smoke в браузере

  1. Открыть https://admin.oknotika.ru/login в private window.
  2. Выполнить wrong password smoke: правильный логин и заведомо неверный пароль должны показать одинаковую общую ошибку и не открыть editor.
  3. Войти правильными данными; убедиться, что доступны только новости/статьи.
  4. Выйти; возврат к admin API/странице должен снова требовать login.

После успешного smoke сделать candidate env активным:

set -euo pipefail
sudo install -o root -g 1000 -m 0640 "$OKNOTIKA_CANDIDATE_ENV" "$OKNOTIKA_COMPOSE_ENV.next"
sudo mv "$OKNOTIKA_COMPOSE_ENV.next" "$OKNOTIKA_COMPOSE_ENV"

Для плановой rotation повторить credential helper с тем же логином и новым паролем, запустить admin и проверить, что открытая до rotation session отозвана. Guarded откат выполняется helper-командой configure-local-credentials.sh --rollback "$OKNOTIKA_CREDENTIAL_SNAPSHOT"; audit reason — credential-rollback.

4. Удаление старого OIDC и relay

Это production-only шаги: точные имена override и relay есть только на VPS. Женя должен сначала определить их по active Compose/systemd configuration. Не угадывать имя и не останавливать сам Xray.

set -euo pipefail
export OKNOTIKA_TELEGRAM_OVERRIDE=/root-controlled/exact-production-telegram-override.yml
export OKNOTIKA_TELEGRAM_RELAY_SERVICE=exact-production-telegram-relay-service
sudo test -f "$OKNOTIKA_TELEGRAM_OVERRIDE"
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --file "$OKNOTIKA_TELEGRAM_OVERRIDE" --env-file "$OKNOTIKA_COMPOSE_ENV" config --services \
  | grep -Fx "$OKNOTIKA_TELEGRAM_RELAY_SERVICE" >/dev/null
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --file "$OKNOTIKA_TELEGRAM_OVERRIDE" --env-file "$OKNOTIKA_COMPOSE_ENV" \
  stop "$OKNOTIKA_TELEGRAM_RELAY_SERVICE"
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --file "$OKNOTIKA_TELEGRAM_OVERRIDE" --env-file "$OKNOTIKA_COMPOSE_ENV" \
  rm --force "$OKNOTIKA_TELEGRAM_RELAY_SERVICE"
sudo install -d -o root -g root -m 0700 "$OKNOTIKA_BACKUP/retired-oidc-relay"
sudo mv "$OKNOTIKA_TELEGRAM_OVERRIDE" "$OKNOTIKA_BACKUP/retired-oidc-relay/"
for name in telegram-oidc-client-id telegram-oidc-client-secret; do
  if sudo test -f "$OKNOTIKA_ROOT/admin-app/data/secrets/$name"; then
    sudo mv "$OKNOTIKA_ROOT/admin-app/data/secrets/$name" "$OKNOTIKA_BACKUP/retired-oidc-relay/$name"
  fi
done
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_COMPOSE_ENV" up --detach --no-build --wait --wait-timeout 120
curl --fail --silent --show-error https://admin.oknotika.ru/login >/dev/null
curl --fail --silent --show-error https://oknotika.ru/ >/dev/null

Убрать override из постоянной команды запуска/автоматизации. Убедиться, что local login работает без него, а Xray продолжает работать без изменений. Retired files хранить зашифрованно до окончания rollback window.

5. Полный rollback на прежний OIDC image

Если любой gate или login не прошёл, не чинить production на месте. Сохранить candidate data для разбора, вернуть source, data, Compose env и nginx из backup. Новые данные не удаляются.

set -euo pipefail

sudo test -f "$OKNOTIKA_BACKUP/source-before.tar"
sudo test -f "$OKNOTIKA_BACKUP/admin-data-before.tar"
sudo test -f "$OKNOTIKA_BACKUP/compose.env.before"
sudo test ! -e "$OKNOTIKA_FAILED_ROOT"
sudo install -d -o root -g root -m 0700 "$OKNOTIKA_FAILED_ROOT"
sudo docker compose --project-name "$OKNOTIKA_ACTIVE_PROJECT" --file "$OKNOTIKA_COMPOSE" --env-file "$OKNOTIKA_CANDIDATE_ENV" stop admin
sudo mv "$OKNOTIKA_ROOT/admin-app/data" "$OKNOTIKA_FAILED_ROOT/admin-data-after-candidate"
sudo mv "$OKNOTIKA_ROOT/admin-app" "$OKNOTIKA_FAILED_ROOT/admin-app-after-candidate"
sudo mv "$OKNOTIKA_ROOT/deploy" "$OKNOTIKA_FAILED_ROOT/deploy-after-candidate"
sudo tar -C "$OKNOTIKA_ROOT" -xpf "$OKNOTIKA_BACKUP/source-before.tar"
